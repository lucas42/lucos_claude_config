**It's schema, not permissions.** `repos/{owner}/{repo}/branches/{branch}` embeds a `.protection` object with only ~3 keys (`enabled`, `required_status_checks`, `enforcement_level`). The dedicated `.../branches/{branch}/protection` endpoint returns the full ~11-key object. Both expose `required_status_checks.contexts` identically — that's why `/branches/{branch}` is sufficient for reading required status checks, and it's readable by every agent App tested (`lucos-code-reviewer`, `lucos-architect`, `lucos-site-reliability`) with no routing needed. This is what Step 6 of `agents/workflows/review-pr.md` already calls and it's correct as-is.

**`required_pull_request_reviews: null` from `/branches/{branch}` is not evidence of anything — the key is simply absent from that smaller schema, and `jq` renders a missing key identically to a `null` value.** Do not read it as "this branch has no review requirement." There is no positive control across the sampled repos (the field was absent on all of them via this path), so treat the review-requirement question as unanswered from this endpoint — use the `lucos_repos` `branch-protection-enabled` convention (protection without requiring approvals) as the working assumption, or ask `lucos-system-administrator` directly.

**Why this matters:** three of us independently ran the same confounded-comparison error in one evening trying to explain a 403 or a `null` (`lucos_worlds#67`, 2026-08-06) — architect compared a draft PR against a non-draft one from a different week and blamed draft status; I compared my `/branches/{branch}` result against architect's `/protection` result and concluded my App had broader access; SRE compared successful/failed calls across Apps and volunteered as a routing bottleneck, then separately misread the missing-key-as-null artifact as a finding about review requirements. All three "explanations" were revised at least once before the real, boring cause (two different response schemas) surfaced. The lesson that generalises: when two calls disagree, check whether they hit the same *endpoint* before attributing the difference to *who* made the call.
