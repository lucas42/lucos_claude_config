description: Use /branches/{branch} (not /branches/{branch}/protection) to read required status checks — the former returns 200 for bot Apps, the latter 403s

  type: reference

**It's the endpoint, not the App.** `repos/{owner}/{repo}/branches/{branch}` returns 200 for every agent App tested (`lucos-code-reviewer`, `lucos-architect`, `lucos-site-reliability`) and exposes `.protection.required_status_checks.contexts` — byte-identical across Apps. This is what Step 6 of `agents/workflows/review-pr.md` already uses and it's correct. The dedicated `.../branches/{branch}/protection` sub-endpoint needs admin-level access and 403s for most agent Apps regardless of which one calls it. `required_pull_request_reviews` comes back `null` at the `/branches/{branch}` level even when reviews *are* required — that field specifically needs the `/protection` path. So: required *status checks* — the `/branches/{branch}` path is reliable and sufficient for any App. Required *review* settings — don't trust an absence there; treat the `lucos_repos` `branch-protection-enabled` convention (protection without requiring approvals) as the working assumption instead, or ask `lucos-system-administrator` (confirmed `administration: write`) directly.

**Why this matters:** "only `lucos-system-administrator` can read branch protection" (and its variant, "only SRE's App can") had been circulating as estate fact across multiple personas — including a comparative claim I made myself ("my App has broader read access than yours") — before `lucos-architect` traced the actual cause to the endpoint, not the caller (`lucos_worlds#67`, 2026-08-06). Three agents made the same confounded-comparison error in one evening: architect compared a draft PR against a non-draft one from a different week and blamed draft status; SRE compared their own successful `/protection` call against another App's failed one and volunteered as a bottleneck; I compared my `/branches/{branch}` result against architect's `/protection` result and concluded my App had broader access. None of the three comparisons controlled for the variable that actually differed. Don't repeat a 403 from the `/protection` path as "bots can't read this" or "only App X can" — try `/branches/{branch}` first, from any App.
