**Historical episode (2026-05, fully resolved — do not re-apply its diagnosis to a new failure without checking logs):** Dependabot's major-group update PRs for lucos_media_seinn used to consistently produce a lock file that downgraded `mocha` from `11.7.x` (on main) to `11.3.0`, dragging in `diff@5.2.2` and `workerpool@6.5.1`, so `npm ci` failed on the lock/manifest mismatch. 5 closed-without-merge occurrences in 7 days (#446, #452, #458, #461, #465). Root cause (issue #462, closed): a global `"minimatch": "^5.1.7"` override in `package.json` forced mocha to an incompatible minimatch; fixed 2026-05-21 by removing the override entirely. **Issue #466 (recurrence tracker) is now CLOSED as completed** — confirmed 2026-09-06 by re-checking its state before citing it (don't trust this memory's age on that point). `lucos_media_seinn`'s `package.json` no longer carries any `minimatch` override at all (confirmed 2026-09-06) — the fix held.

**New, unrelated failure (2026-09-06, PR #617, mocha 11.8.0→12.0.0 in a 10-package major group):** All tests fail with `Error [ERR_INPUT_TYPE_NOT_ALLOWED]` from Node's ESM loader, thrown by the repo's test script `node --expose-gc --input-type=module ... node_modules/mocha/bin/mocha tests`. This script is unchanged and passes on `main` under mocha 11.8.0 — the failure is specific to mocha 12's `bin/mocha` changing how it resolves/re-execs. Not a lockfile/minimatch issue (no override involved this time) — it needs a source fix to the test invocation itself. Posted REQUEST_CHANGES and handed to `lucos-developer` to find a mocha-12-compatible invocation.

**How to apply:** Don't assume a new lucos_media_seinn major-group CI failure is the old minimatch bug — read the actual log first; the override that caused the 2026-05 episode is gone. Do NOT close-and-recreate a major-group PR on a hunch — for a *manifest-override* class failure, close-and-recreate never helps (same inputs); for other classes (like this one), check whether it needs a real code fix before deciding.

**Separately, `lucos_notes` hit the *same class* of failure the 2026-05 episode did (2026-09-06, PR #515):** a leftover `"minimatch": "^5.1.7"` override in its own `package.json`, incompatible with a minor-and-patch bump of `test-exclude`/`babel-plugin-istanbul`. `lucos_notes` is a different repo from `lucos_media_seinn` — the two just happened to carry the same override pattern; checked other JS repos' `package.json` overrides (2026-09-06) and none of the others currently have a bare `minimatch` override, so this isn't a live estate-wide convention, just a second repo independently carrying the same now-stale pin. Handed to `lucos-developer` citing the seinn#462 precedent.
